Coverage and freshness

Memetic State's view is limited to the sources and periods it has indexed. Coverage can differ between venues, assets, and features.

Three times matter: when an event happened, when it was collected, and when the page last refreshed. Refreshing a page does not make an old observation new.

What is connected today?

PONS is the main indexed product. PAIR remains a limited supplementary API source. The public Signals, Atlas, Lifecycle, and History views are PONS views.

Source What Memetic State collects What that does not establish
PONS V2 Factory events and an indexed curve-trade archive; the factory feed and trade archive advance separately. Premium adds bounded recent curve checks. A recent factory event does not make the trade archive current. Post-graduation pool swaps are not reconstructed in premium.
PONS V1 Separate historical launch and swap reconstruction, with generation-specific coverage. V1 history is not the PONS V2 premium dataset.
PAIR API sample Up to 12 selected, validated tokens from a discovery request for the top 50 by market cap, with per-token metrics and dated observations. Selected launch evidence can be reconciled onchain. This is not a complete PAIR factory or trade index. Selection can change, and available observations can be old or missing.
Robinhood asset registry and quotes Reference asset identities and separately dated quote observations where available. A shared label does not prove backing, shared liquidity, or correlated returns.

PAIR observations appear as a separately labeled source in premium cross-source ecology when a recorded token or habitat matches. Habitat matches provide taxonomy context only. We retain the source name so readers can tell where the evidence came from; PAIR is not presented as a second fully indexed factory.

In the interface, quote-asset ecology means PONS launches grouped by quote asset. The word “pair” in a pool, quote-pair field, or token record does not mean the PAIR protocol.

Working while the archive catches up

The factory feed has its own cursor for confirmed launches, curve completions, graduations and locks. It can be recent while the detailed trade archive remains delayed. Check the feed's observed chain time and block gap; its freshness does not establish that trade history is current.

Premium's Recent curve check reads up to 2,000 recent blocks directly from a factory-discovered PONS V2 curve. It shows buys, sells, distinct actor addresses, exact window times, and transaction links. It uses one RPC provider per successful observation and keeps the last dated result when a refresh fails. It does not cover swaps after graduation or guarantee that a provider returned every event. Oversized, malformed, conflicting or failed responses are withheld.

The detailed archive continues from its committed cursor. Recent checks do not skip missing ranges, refresh historical scores, or replace the evidence saved in a case. A full repair requires collection to run consistently and commit blocks faster than the chain adds them, followed by replay of the backlog. No catch-up completion date is promised.

While the observatory is open in a visible browser tab, it requests a bounded archive update at most once per minute. Shared server locks prevent visitors from duplicating the same collection job. This helps active sessions make progress, but it is not a guarantee of continuous collection when nobody is visiting. Always use the displayed observation times to assess freshness.

When reviewing a result, check its source, observation window, and latest indexed time. Missing or delayed data should lower confidence in any interpretation built from it.

Coverage label Meaning
Current coverage Recent collection is available for the stated source and period.
Delayed The latest collected information trails the source.
Historical Earlier records are available; current monitoring is not established.
Incomplete Some expected records or fields are missing.

These are the documentation's coverage categories. Individual pages may expose them differently as the interface develops.

The current premium release covers indexed PONS V2 curve events, with dated holder observations where available. V1 history and supplementary API observations retain their own coverage. StonkFun, OTC, and broader aggregation remain source-specific work; they are not included in this premium release.

Premium access cannot recover information the project has never collected. Longer history means the history actually available for the selected source, with gaps identified where known.
